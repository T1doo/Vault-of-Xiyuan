# F0：现状盘点——阶段计划

## 目标

完成 T00，明确“当前有什么、从哪里运行、哪些资源可用、F1 首先做什么”。本阶段以只读检查为主，允许保存审计证据、更新本阶段文档，以及必要的短规则入口；不安装项目环境、不下载大数据/权重、不运行模型或仿真、不启动后台队列。

已知起点：四个官方源码仓库已下载；2026-09-06 有宿主机硬件审计；目前只有文档与源码静态检查，没有可运行的项目实现、训练数据或模型验证。两卡是共享服务器并发预估，无硬截止日。历史证据见 [LOG.md](LOG.md)，不重新下载已有源码，也不把旧占用快照当成当前空闲状态。

共用要求引用 [工程手册 2—3、T00](../CODEX_EXECUTION_GUIDE.md) 和 [实验计划 F0/F1](../EXPERIMENT_PLAN.md)。下面的复选框依据本轮 F0 证据更新；具体结果、失败/重试和阶段总结见 [LOG.md](LOG.md)。勾选表示盘点/规划完成，不表示 F1 环境或模型已验证。

## 实施步骤

按 1→2→3→4→5→6 推进；某项受阻时记录原因，可继续不依赖它的只读检查，不反复等待共享 GPU 空闲。

### 1. 保护现场，核对已有材料

- [x] 确认工作区、文档仓库、四个上游仓库的真实路径、Git 根、分支、提交和未提交修改；区分文档整理与项目代码。
- [x] 检查已有硬件审计、源码版本清单、文档备份是否存在且可读，登记可复用项与缺项。

检查时沿用经过验证的精确 safe.directory 处理方式，先检查临时配置是否仍存在；不改全局 Git 配置、不重置工作树、不覆盖用户文件。产出写本日志：路径、版本、dirty 状态、已有证据位置。本项完成标准是能清楚说明哪些材料真实存在，哪些只是计划。

### 2. 确定启动位置，验证规则读取

- [x] 选定 F1 实际使用的工程根；优先沿用已有 openpi 路径，是否需要工作副本依据现有状态决定，不为目录美观搬迁。
- [x] 检查该目录适用的上游规则和项目短入口；必要时保留原规则并补充权威规则/文档的明确读取路径。
- [x] 从实际工程根启动一次无旧聊天上下文的新会话，只核验能否按入口读取工作区规则、README 当前阶段、两份主文档及本阶段 PLAN/LOG；实际使用 worktree 时也验证其入口。

记录客户端版本、启动目录、自动加载来源、显式读取来源和核验输出位置。不能用本会话“记得规则”代替新会话证据，也不为测试另建一批 worktree。若新会话工具不可用，明确未验证，继续其他盘点；不能据此声称开发入口已就绪。

### 3. 更新服务器资源快照

- [x] 在能看到宿主机设备与进程的执行环境查询 GPU 型号/UUID、显存、利用率和计算进程；记录时间及可见性限制。
- [x] 核查 CPU、RAM、文件系统类型、可用空间和项目目录访问条件，区分 NFS 持久存储与本地临时空间。
- [x] 明确共享资源使用方式：启动前再查占用，默认一张卡一个主要作业；两卡不是保证，不把八卡当项目额度。

GPU 当前忙不阻塞文档、依赖审查与 CPU 侧准备；没有可用卡时登记 GPU 工作等待。不得终止陌生进程、修改驱动或执行 GPU 压测。此项只给资源快照和约束，不给训练/教师/仿真吞吐结论；I/O 和模型测速留 F1/F2。

### 4. 明确环境与存储路径

- [x] 盘点本用户可用的 Python、环境管理工具及系统依赖线索；仅查版本/位置，不将系统 Python 当已验证项目环境。
- [x] 为 policy-train、teacher、sim-clean、sim-plus 分别选定安装位置，并规划 clean/plus 独立 LIBERO 用户配置。
- [x] 在本日志列清原始数据、转换数据、基础权重、方向监督、教师缓存、运行输出和本机配置的拟用路径，逐项标“已有/拟建”。

沿用实际工作区路径，优先满足隔离和可恢复性，不建设新的目录管理体系。缓存临时文件与最终提交应在同一目标文件系统；公开仓库只存摘要，不收凭据、数据或模型。产出为日志中的一张路径表，F0 不要求创建全部目录。

### 5. 核对 F1 所需来源与依赖

- [x] 读取已固定源码的官方安装说明和依赖文件，形成四环境的候选版本组合；记录与宿主机驱动的待验证项，不执行安装或升级系统。
- [x] 核对 π₀-FAST 基础权重、FAST tokenizer、Spatial 原始演示、LIBERO/Plus 资产和教师权重的官方来源；轻量检查访问条件，记录 revision/commit 与后续校验方式。
- [x] 检查实际下载/转换/训练入口是否存在，先读源码和参数定义；依赖未装时不强行运行 --help，更不把静态阅读称为 CLI 验证。

下载范围仅覆盖既定四组。学生训练不能误用 Plus 扩增训练集；原始演示需要支持后续状态回放和 A 标注。是否具备真实状态、官方初态数量与唯一 reset，要在 F1 获取资源后核验，F0 不凭文件名下结论。来源可访问不代表资源已下载或质量通过。

记录 docs_commit、各上游 commit；implementation_commit 尚无项目实现则留空并解释。基础资源缺失已获负责人授权自行准备，不重复询问；实际遇到访问限制、必要系统依赖或权限问题再提出具体需求。

### 6. 汇总 F0，交接 F1

- [x] 在本日志更新最新状态、路径/版本、已验证命令、证据位置、待解决项；原始审计使用实际文件名保存到仓库外，不为匹配手册示例复制空文件。
- [x] 对照下方完成条件逐项写出结论；完成后在本日志末尾追加阶段总结。
- [x] 确定 F1 第一个实际动作及其依赖。已有验证命令直接引用本日志；尚未可运行的安装/下载步骤明确标计划，先验证再执行。

F0 收口且 F1 开始时，才将 README 当前阶段入口切换至 F1；本次编写计划不触发切换。

## 完成条件

- 已有仓库、未提交工作和证据得到保留，路径/版本可追溯。
- 实际工程启动位置明确，新会话规则读取有证据；未验证时不标该项完成。
- 有带时间的宿主机资源快照或明确的不可见限制，共享使用边界清楚；不要求此刻恰有两张空闲卡。
- 四环境隔离、数据/权重/监督/输出路径和官方来源明确，安装与资源质量待验证项没有被写成成功。
- 阶段日志给出每项结论及 F1 下一操作；影响该操作的阻塞已解决，其余待验项可在 F1 对应步骤处理。

F0 完成仅说明准备起点可信，不代表环境安装成功、模型可运行、数据链路正确或 G1/G2 通过。不以论文成绩、A/B 增益或估计卡时作为 F0 门槛。
